# 网页数据管理台

管理台用于查看本地历史覆盖、预览更新范围、启动后台更新和检查结果。
界面和任务执行使用同一个数据目录，不需要在页面中输入命令。
只监听本机 `127.0.0.1`；此版本面向本地使用，没有公网账号与权限系统。

## 启动

首次安装前端依赖并构建：

```bash
npm ci --prefix webadmin/frontend
npm run ui:build
npm run ui
```

打开 `http://127.0.0.1:8765`。端口占用时可以选择其他端口：

```bash
npm run ui -- --port 8767
```

默认管理仓库的 `data/`，数据库为 `data/cn.duckdb`。
使用其他目录时明确指定它，覆盖和更新均只使用这个目录：

```bash
npm run ui -- --port 8767 --data-dir /path/to/data
```

## 页面流程

1. 选择数据类别、日期范围和适用的证券代码，点击“查看此范围覆盖”。
2. 选择“增量补充”“指定范围刷新”或“缓存重新解析”。
3. 可直接点击“开始下载”；缓存模式为“开始解析”，日历为“开始同步”。也可先点“生成更新预览”核对范围。
4. 后台处理不阻塞页面；下载显示实际已传输大小、总大小和平均速度，解析入库显示处理数量。服务器不提供总大小时显示已传输字节而不伪造百分比。
5. 完成后检查记录数、日期缺口和关键字段缺失值的前后变化。

没有本地交易日历时，页面提供“同步交易日历”按钮，先生成日历更新预览。
日历复用现有 BaoStock 来源，仅添加所选范围的真实交易日，不生成工作日假日历。

## 支持的数据与更新方式

| 数据 | 增量补充 | 指定范围刷新 | 缓存重新解析 |
| --- | --- | --- | --- |
| 沪深股票、ETF 日线 | 检查批量包，只插入范围内缺失记录 | 重新下载历史包，更新选定范围中的已有值 | 使用本地 `downloads/hsjday.zip`，重新解析并更新范围内值 |
| 季度财务 | 补缺失季度，并刷新所选范围最后四个季度 | 下载并更新范围内所有已完成季度 | 使用本地 `mootdx_financial/gpcwYYYYMMDD.zip`，应用当前字段映射 |
| 深市 ETF 历史 PCF | 按 ETF 和交易日下载，跳过通过基础校验的归档 | 重新下载范围内各日清单 | 不提供：未缓存原始 XML |
| 交易日历 | 同步指定范围的真实交易日 | 不提供 | 不提供 |

日线可留空代码以处理包中的全部沪深股票和 ETF，也可指定最多 100 个代码。
始终过滤日期范围，不把批量包的全部历史写入所选范围之外。
财务按全市场季度包更新，不能按单证券更新，以免将部分季度误标为全市场完成。
历史 PCF 必须指定 `15` 开头的 `.SZ` ETF；沪市历史源尚未接入，不用最新清单代替历史。
PCF 保存到 `<data-dir>/etf_pcf/<ETF代码>/<实际清单日期>.parquet`。

范围刷新和缓存重新解析会更新范围内已有值；不会删除数据库再重建，
不会同时刷新其他类别，也不自动发布、导出整库或部署到云端。

## 覆盖统计如何解读

- 记录数、证券数和日期范围只统计当前选择的范围与证券。
- 日线日期缺口是本地交易日历中**整个筛选范围内没有任何证券记录**的交易日，
  不是逐证券缺失率，也不是扣除停牌、上市和退市后的严格历史覆盖率。
- 财务日期缺口按已完成季度期末统计。有公司记录不表示全市场该季度完整。
- 财务字段列数统计已建立的公开映射列，不表示每家公司每列都有值。
- 字段缺失只检查六个关键字段，包括 NULL 和非有限数值；源零值不当作缺失。
- PCF 按明确筛选的 ETF 或已归档的 ETF × 本地交易日统计，校验日期、基金代码、
  必要字段、重复证券、数量及净值。无归档也未指定 ETF 时无法推算全市场缺口。
- 最新快照、当前板块和 F10 不计入历史回测覆盖。

这些指标不能单独证明完整 PTrade 兼容、历史证券池或公告时点无未来数据。
其他边界见 [财务覆盖](PTRADE_FINANCIAL_COVERAGE.md)和 [PCF 历史覆盖](ETF_PCF_DATA.md)。

## 后台任务与恢复

一次只运行一个任务。预览有效期 10 分钟且只能使用一次；开始时重新核验范围。
页面不能执行任意命令或指定写入路径。只读覆盖检查不会创建、迁移或修改数据库。
更新期间显示开始前的覆盖快照，避免与 DuckDB 写进程争用；完成后自动重新读取。

日志和摘要保存于 `<data-dir>/ui-jobs/`，页面保留最近 30 个任务、每个任务最近 300 行日志。
取消终止当前管理台启动的进程，已提交记录保留。财务按季度事务提交；PCF 原子替换归档。
失败后可点“使用此任务参数”，重新预览并增量执行；它不是下载字节级续传。
服务重启将上次未结束任务标为“服务中断”，不会误报完成。

外部 CLI 仍可使用。如果外部进程持有数据库写锁，管理台报告失败而不会绕过锁。
不要同时用外部 CLI 和页面更新同一数据库。

## 开发与验证

后端入口为 `python -m simtradedata.web`，前端位于 `webadmin/frontend/`。
构建产物位于 `simtradedata/web/static/`，由本地服务提供。

```bash
npm run ui:build
npm --prefix webadmin/frontend exec playwright install chromium
npm run ui:test
npm run ci:full
```

浏览器测试用临时数据库和本地 ZIP 验证“覆盖 → 预览 → 真实缓存导入 → 更新后检查”，
以及手机布局、无效参数和来源检查，不下载或修改生产数据。
CI 已增加独立前端构建和浏览器测试作业。远端下载仍受数据源可用性影响。
