# 网页数据管理台

管理台用于查看本地历史覆盖、自动补齐数据和检查结果。
界面和任务执行使用同一个数据目录，不需要在页面中输入命令。
只监听本机 `127.0.0.1`；此版本面向本地使用，没有公网账号与权限系统。

## 启动

安装Python 3.10+、uv与Node.js 20+（含npm）后，在项目根目录直接启动：

```bash
npm run ui
```

启动入口自动安装前端依赖、按需构建，并同步Python依赖。默认管理 `data/cn.duckdb`，端口从8765开始自动选择可用值；打开终端显示的地址，不需要填写参数。也可显式指定端口：

```bash
npm run ui -- --port 8767
```

默认管理仓库的 `data/`，数据库为 `data/cn.duckdb`。
使用其他目录时明确指定它，覆盖和更新均只使用这个目录：

```bash
npm run ui -- --port 8767 --data-dir /path/to/data
```

## 界面语言

右上角可切换中文、English、Deutsch。首次访问跟随浏览器语言，未支持的语言使用英文；后续记住手动选择。切换不重置表单或中断任务。界面提示、进度和数字/时间格式随语言变化；证券名称、代码和原始技术日志保留原文。

## 重启管理台

页面右上角的“重启管理台”重新加载后端代码，保留启动时的命令、端口和数据目录。
有运行中或取消中的更新任务时按钮禁用，后端也会拒绝重启。空闲时点击无需再输入命令，
页面等待新服务实例就绪后自动刷新；30 秒内未恢复时提示检查启动终端。
重启保留已提交数据和缓存，清除内存中的当前任务和数据源状态。

网页无法在后端停止时启动服务，因此不提供会误导用户的“启动”按钮。
首次启动仍使用上面的 `npm run ui` 命令；从旧版本升级到带重启接口的版本需要手动重启一次。

## 页面流程

1. 点击“更新回测数据”，统一更新全部股票与ETF日线，无需逐只搜索或选择。季度财务和ETF申赎清单位于“其他数据”；PCF需选择ETF，最多100只。
2. 页面自动核对本地数据，显示待补齐日期范围；财务说明待处理季度数、优先复用缓存数和需要下载的包数。
3. 已有有效记录自动跳过，缓存优先复用。没有缺口时按钮显示“已是最新”并禁用。
4. “已保存的行情”分别展示股票与ETF的证券数、日线记录数和实际日期范围；本地数据详情与任务结果也分开统计。LOF、指数等不混入ETF统计。
5. 下载显示实际字节数、总大小和速度。财务同时显示整体季度处理数和当前季度公司进度，当前季度达到 100% 不表示整个任务完成；所有单元处理后仍显示校验阶段，完成后自动重新检查。

默认检查数据库已有历史区间及其尾部更新。日线只查询 DuckDB 中的日期缺口及字段质量，
动态选取缺口的最早、最晚日期；普通检查不打开或解压 ZIP。实际补齐时才读取源包，已有有效记录仍跳过。
数据库无法单独证明每只证券每天都应有记录；停牌、上市和退市需要独立依据，普通检查不宣称严格逐证券完整。
日期缺口驱动智能补齐；已有记录的缺失或异常字段单独显示为质量告警，不因此反复下载历史包。
当前源可能没有这些证券/日期记录，不能把重复下载当作修复，也不将缺失成交量或成交额自动填零。
财务按缺失或需要重新解析的季度检查，PCF 按 ETF 和真实交易日检查。
首次获取使用项目默认的 2015 年起范围；若要补更早历史，展开高级选项，勾选“手动指定回测范围”。
自动检查无法凭已有记录推断用户需要多早的历史。

交易日历缺失时随任务获取，真实交易日和非交易日保存在 DuckDB 的 `exchange_calendar` 表中。
日历复用 BaoStock 来源，不生成工作日假日历。

## 定向修补不完整记录

日线日期齐全但有字段质量告警时，点击“修补不完整数据”。后台重新读取 DuckDB 的异常证券与日期，
仅读取这些证券的本地通达信文件；缓存未补出的记录，查询 BaoStock 未复权备用源的异常日期范围。
不会重新下载整包，也不将日期范围内已有有效记录重新写入。

修补保持已有有效字段、涨跌停价和昨收不变；源日期不匹配、与已存有效值冲突或源字段无效时拒绝覆盖。
没有交易的零值需要同证券、同日期的已有 HALT 停牌记录，或备用源明确的 `tradestatus=0` 依据；不能仅因原字段为空就填零。
源基础资料确认旧代码退出交易或指数停止发布时，退出日起全部行情字段为空的记录单独分类，
保留原记录并更新真实生命周期元数据，不作为待修补行情。不能用同号股票替换指数，或把新代码行情写到旧代码。退出日期使用源基础资料核验，不由本地最后行情日推断。
结果显示已修复条数、来源数量和仍未修复条数，未解决部分按证券给出原因；源没有历史记录时保留告警。
任务状态与日志仍只在内存保留，不保存修补历史。

季度财务的新字段可通过高级选项“只重新解析缓存”补入已有季度；若包缺失，先执行智能补齐。
源本身缺少的字段不能通过重新解析创造出来，仍需进一步接入对应财报来源。

## ETF 选择与回测

首页分别显示股票和ETF统计，可展开“未获取历史的ETF”。上市前、未开始发行或募集失败的证券会列出核验依据，不计作行情下载失败；上市后重新检查。基金份额代码不一定独立交易，例如159006使用159005的行情，不复制数据生成另一只证券。

普通 ETF 价格回测使用“日线行情”，其全市场下载包含股票和 ETF；不要求提供 PCF。
默认无需搜索或选择ETF：在线全市场日线更新会自动读取沪深ETF目录，补充历史包遗漏的ETF，并按DuckDB中的真实交易日缺口获取。单只ETF失败会单独报告，继续其他证券；目录源失败会报告覆盖不完整。
在“高级选项”中展开“只更新指定ETF”可按代码、简称或基金名称搜索，筛选沪市/深市并多选，只更新所选 ETF。
留空则更新历史包中的股票与 ETF，并补充目录中未入包的ETF。证券不在历史包中时，在线更新会通过通达信日线接口补充，ETF未返回对应缺口行情时依次尝试腾讯证券、东方财富未复权历史接口；接口返回的价格保持元单位，已有记录在自动补齐模式下保留。离线重解析不调用接口，会明确报告包中缺少的证券。
沪市 ETF 识别已包含 53、55 开头的新代码段。ETF 申赎清单提供同一列表，历史 PCF 目前仅开放深市查询；
沪市项显示“仅最新 PCF，历史尚未接入”，不会因此限制它的日线回测。

目录结合上交所官方 ETF 清单（完整分页）与通达信深市 ETF 行情目录。
深市使用当前 158/159 ETF 代码段，排除分级基金和 PCF 现金项；通达信简称补充搜索与显示。
目录展示数据通道能力和 DuckDB 中已存的日期范围，不把它们当作连续历史完整性证明，
也不宣称当前目录包含全部已退市 ETF。具体历史覆盖仍需按回测日期核验。

首次读取目录异步执行，不阻塞本地数据检查；来源目录只在内存缓存一小时，
“刷新目录”可以重新读取，不保存目录任务历史。某个来源失败时显示不完整提示；
全部失败时显示错误，不偷偷退回单只 159919.SZ。手动代码输入保留在折叠选项中。

## 数据源自动检查

管理台启动后检查一次，此后每 24 小时检查；页面的“检查数据源”按钮可随时复查。
服务停止时不会检查，不依赖浏览器页面保持打开。检查本身不执行更新、不下载历史整包、不写生产数据。
ETF 某历史日期缺公告不计为网络故障，不触发全源冷却；下载任务先处理最新日期，再回溯历史。缺公告日期仍明确报告未获取。

| 来源 | 检查内容 | 新鲜度判断 |
| --- | --- | --- |
| 通达信日线 | 流式请求仅读取 ZIP 前四字节，识别返回 HTML 等错误响应 | 比较包大小和发布时间与本地缓存；文件头有效不能证明包内最新交易日，无法确认时显示“新鲜度待核对” |
| 通达信季度财务 | 复用 Mootdx 官方文件目录，校验报告期、文件名、大小和 MD5 | 最新已发布季度是否缓存；现有本地包与官方 MD5 是否一致，可发现同大小修订；未发布季度不算过期 |
| 深市 PCF | 获取 159919.SZ 的目录和最新 XML，复用日期、基金代码、篮子字段校验 | 对照完整的本地真实交易日历，节假日不误报；日历不完整或数据库忙时不宣称新鲜度已确认 |

只保留三类来源的最新检查结果、最后检查时间和连续失败计数，全部在服务内存中；
不保存检查历史，服务重启后重新检查并重置失败计数。前两次失败显示“待复查”，连续三次显示“异常”。
PCF 健康检查是单只 ETF 样本，不代表所有 ETF 都能获取。日线文件头和财务目录检查不代替整包解析校验。
发现“待更新”后可通过已有智能补齐流程处理；财务修订需要在高级选项使用强制重新下载。

## 支持的数据与更新方式

| 数据 | 增量补充 | 指定范围刷新 | 缓存重新解析 |
| --- | --- | --- | --- |
| 沪深股票、ETF 日线 | 检查批量包，只插入范围内缺失记录 | 重新下载历史包，更新选定范围中的已有值 | 使用本地 `downloads/hsjday.zip`，重新解析并更新范围内值 |
| 季度财务 | 补缺失季度，复用缓存补字段；已导入且未变化的完整季度跳过 | 下载并更新范围内所有已完成季度 | 使用本地 `mootdx_financial/gpcwYYYYMMDD.zip`，应用当前字段映射 |
| 深市 ETF 历史 PCF | 按 ETF 和交易日下载，跳过通过基础校验的归档 | 重新下载范围内各日清单 | 不提供：未缓存原始 XML |
| 交易日历 | 同步指定范围的真实交易日 | 不提供 | 不提供 |

日线可留空代码以处理包中的全部沪深股票和 ETF，也可指定最多 100 个代码。
始终过滤日期范围，不把批量包的全部历史写入所选范围之外。
财务按全市场季度包更新，不能按单证券更新，以免将部分季度误标为全市场完成。
历史 PCF 必须指定 `15` 开头的 `.SZ` ETF；沪市历史源尚未接入，不用最新清单代替历史。
PCF 保存到 `<data-dir>/etf_pcf/<ETF代码>/<实际清单日期>.parquet`。

范围刷新和缓存重新解析会更新范围内已有值；不会删除数据库再重建，
不会同时刷新其他类别，也不自动发布、导出整库或部署到云端。

## 覆盖统计如何解读

- 记录数、证券数和日期范围只统计当前选择的范围与证券。
- 日线日期缺口是本地交易日历中**整个筛选范围内没有任何证券记录**的交易日，
  不是逐证券缺失率，也不是扣除停牌、上市和退市后的严格历史覆盖率。
- 财务日期缺口按已完成季度期末统计。有公司记录不表示全市场该季度完整。
- 财务字段列数统计已建立的公开映射列，不表示每家公司每列都有值。
- 字段缺失只检查六个关键字段，包括 NULL 和非有限数值；源零值不当作缺失。
- PCF 按明确筛选的 ETF 或已归档的 ETF × 本地交易日统计，校验日期、基金代码、
  必要字段、重复证券、数量及净值。无归档也未指定 ETF 时无法推算全市场缺口。
- 最新快照、当前板块和 F10 不计入历史回测覆盖。

这些指标不能单独证明完整 PTrade 兼容、历史证券池或公告时点无未来数据。
其他边界见 [财务覆盖](PTRADE_FINANCIAL_COVERAGE.md)和 [PCF 历史覆盖](ETF_PCF_DATA.md)。

## 后台任务与恢复

一次只运行一个任务。点击更新时后台重新核验范围。
页面不能执行任意命令或指定写入路径。只读覆盖检查不会创建、迁移或修改数据库。
更新期间显示开始前的覆盖快照，避免与 DuckDB 写进程争用；完成后自动重新读取。

不保存更新记录或任务历史文件。当前任务的进度、结果和最近日志仅保留在服务内存中；
刷新页面不展示已完成任务，服务重启后不恢复任务记录。
完成度来自实际 DuckDB 记录与源文件核对，不用外部 JSON 下载状态判断。
财务沿用数据库季度进度表记录源文件及解析版本签名，并核对实际记录数，避免重复解析。
临时任务请求文件完成后删除。

取消终止当前管理台启动的进程，已提交记录保留。财务按季度事务提交；PCF 原子替换归档。
部分失败可展开未完成名单并点击“继续补齐”，只重试失败证券；它不是下载字节级续传。“重新检查”只读取本地状态，不启动下载。

外部 CLI 仍可使用。如果外部进程持有数据库写锁，管理台报告失败而不会绕过锁。
不要同时用外部 CLI 和页面更新同一数据库。


数据库恢复、财务性能复测和前端开发见[运维说明](OPERATIONS.md#网页管理台维护)。数据能力和ETF历史限制见[数据覆盖](PTRADE_DATA_COVERAGE.md)。

ETF补齐只保存与真实缺口日期匹配的记录；范围内其他日期有数据不代表缺口已经修复。已知休市、已有HALT记录和已确认退市日后的日期排除。备用源在同一任务中连续三次连接失败后停止请求，下一次任务重新检查；空数据不触发连接熔断。未获取日期及原始来源诊断可在未完成名单中展开查看，不生成缺失价格或另存下载状态。

有已核验上市日期时，从上市日核对历史缺口；首条已存行情不是上市日期的证明。官方交易日历优先于行情推导日期；日历未完整覆盖请求范围时，任务报告覆盖待核验并要求先同步日历，不把空缺口集合判为完成。自动选出的端口在界面重启时保持不变。
